# iOS-автозаполнение Passman

Реализация `ASCredentialProviderExtension` — стандартного механизма iOS
для автозаполнения паролей. Вся расшифровка и работа с хранилищем — на
Rust (`src-tauri/src/mobile_ffi.rs`), здесь — Swift-обвязка под
UIKit/Keychain/LocalAuthentication контракты расширения.

**⚠️ Не собрано и не протестировано здесь** — в этой среде нет macOS/Xcode
вообще (это уже обсуждалось ранее: `cargo check --target aarch64-apple-ios`
не проходит даже для уже существующего кода проекта, без него, —
Apple SDK недоступен на Windows). Код написан по документированным,
стабильным API (`ASCredentialProviderExtension`, Keychain,
`LocalAuthentication`), но скомпилировать и тем более запустить его можно
только на Mac с Xcode — что и планируется сделать позже согласно исходному
плану проекта.

## ⚠️ Главный незакрытый пробел: общее хранилище данных

iOS-расширения выполняются в ОТДЕЛЬНОЙ песочнице от основного приложения —
`app_data_dir()`, который Rust-ядро использует на остальных платформах,
здесь резолвится в приватный контейнер ОСНОВНОГО приложения, недоступный
расширению. Единственный официальный способ поделиться файлами между
таргетами — **App Group** (общий контейнер, настраиваемый в Xcode у ОБОИХ
таргетов).

`AppStorage.swift` в этом каталоге уже рассчитан на App Group
(`group.com.trader.passman`), но **это только половина работы** — сам
основной Tauri-app пока продолжает писать `vault.json` в свою обычную
приватную директорию, а не в общий контейнер. Эта часть НЕ сделана (нужны
изменения на стороне основного приложения + создание реального Xcode-
проекта, то есть GUI-операции, которые невозможно надёжно сделать вслепую,
без возможности собрать и проверить). Без этого шага расширение будет
читать пустой/несуществующий файл.

**Что нужно сделать при реальной сборке на Mac** (ориентировочно, потребует
собственной проверки по месту):

1. В Xcode добавить капустability "App Groups" к основному таргету
   приложения и к таргету расширения, с одинаковым ID группы.
2. Либо изменить путь, который использует `app.path().app_data_dir()` в
   основном приложении на iOS (нужна кастомизация пути специально под iOS
   — вероятно, через Tauri-плагин или прямое изменение сгенерированного
   `AppDelegate`), чтобы он указывал на
   `FileManager.default.containerURL(forSecurityApplicationGroupIdentifier:)`
   вместо своей приватной директории, либо держать копию/симлинк
   `vault.json` в общем контейнере, синхronизируемую при каждом сохранении.
   Первый вариант чище (один путь истины), второй — меньше трогает Rust-
   ядро, но добавляет риск рассинхронизации.

## Поведение (как и на Android)

1. Биометрия (если уже есть кэш) → при любой ошибке/отсутствии — мастер-
   пароль.
2. После первого успешного ввода пароля — предложение включить биометрию.
3. Поиск записей по домену (`ASCredentialServiceIdentifier`) → при
   нескольких совпадениях — список выбора → расшифровка конкретного пароля.

**Ограничение модели данных**: заполняется только пароль (`user` в
`ASPasswordCredential` — пустая строка), записи Passman не хранят
отдельный логин.

## Структура

```
src-ios/
  PassmanFFI/passman_ffi.h                       — C-заголовок FFI (Rust)
  PassmanAutofillExtension/
    CredentialProviderViewController.swift       — точка входа расширения
    MasterPasswordViewController.swift            — фоллбэк-UI
    EntryPickerViewController.swift               — выбор записи при нескольких совпадениях
    EntryMatch.swift                              — модель результата поиска
    BiometricVaultKeyStore.swift                  — Keychain + LocalAuthentication
    VaultBridge.swift                             — Swift-обёртка над C FFI
    AppStorage.swift                              — путь к общему хранилищу (см. пробел выше)
    PassmanAutofillExtension-Bridging-Header.h
    PassmanAutofillExtension.entitlements
    Info.plist.fragment                            — референс, не для копирования целиком
```

## Интеграция в Xcode (на Mac, после `tauri ios init`)

1. `cd src-tauri && bun run tauri ios init` — создаст Xcode-проект
   (`src-tauri/gen/apple/`).
2. Открыть проект в Xcode → File → New → Target → **Credential Provider
   Extension**, назвать `PassmanAutofillExtension`.
3. Заменить сгенерированные Xcode заглушки файлами из
   `PassmanAutofillExtension/` этого каталога (кроме `.entitlements` —
   слить вручную с тем, что Xcode уже создал).
4. Подключить `passman_ffi.h` через bridging header (см. файл
   `*-Bridging-Header.h`) — указать путь в Build Settings таргета
   расширения.
5. Добавить капустability App Groups на оба таргета (см. раздел выше) —
   **обязательно и основному приложению, и расширению**, один и тот же ID.
6. Убедиться, что Rust-библиотека (staticlib из `src-tauri`) слинкована в
   ОБА таргета — основное приложение уже линкует её (так работает Tauri),
   расширение должно слинковать её отдельно (Xcode → таргет расширения →
   Build Phases → Link Binary With Libraries).
7. **Обязательно** собирать с `RUSTFLAGS="-C panic=unwind"` — см. комментарий
   в начале `src-tauri/src/mobile_ffi.rs` и `.github/workflows/build.yml`.
   Без этого паника в Rust-коде обрушит процесс расширения куда более
   жёстко, чем просто ошибка автозаполнения.
8. Закрыть пробел с общим хранилищем (раздел выше) — без этого шага
   расширение не найдёт реальные данные.
