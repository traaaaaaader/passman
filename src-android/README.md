# Android-автозаполнение Passman

Реализация системного автозаполнения (`android.service.autofill.AutofillService`,
API 26+) — заполняет поле пароля на любой странице браузера, если домен
совпадает с сохранённой записью. Вся расшифровка и работа с хранилищем —
на Rust (`src-tauri/src/mobile_ffi.rs`), здесь только тонкая обвязка под
Android-контракты (`Service`, `Activity`, Keystore, биометрия).

**⚠️ Не собрано и не протестировано здесь** — в этой среде нет Android
Studio/эмулятора. Код написан по документированным, стабильным API
(Android Autofill Framework, AndroidX Biometric, Android Keystore), но
гарантировать компиляцию без реальной сборки нельзя. Проверено живой
компиляцией только то, что можно проверить без GUI: Rust-сторона
(`cargo check --target aarch64-linux-android`) — она прошла чисто.

## Поведение при автозаполнении

1. Пользователь фокусируется на поле пароля в браузере на телефоне.
2. Если уже включена биометрия для автозаполнения — запрос отпечатка/Face
   через системный `BiometricPrompt`.
3. Любая ошибка биометрии (не настроена, не пройдена, пользователь нажал
   "Ввести мастер-пароль") → экран мастер-пароля Passman.
4. После первого успешного ввода мастер-пароля — предложение включить
   биометрию на будущее (можно отказаться).
5. Если найдено несколько подходящих записей — список для выбора; если
   одна — сразу заполняется.

**Ограничение модели данных** (как и в браузерном расширении): запись
Passman хранит название/пароль/описание/ссылку без отдельного поля логина
— заполняется только пароль.

**Ограничение сопоставления**: домен определяется через `ViewNode.webDomain`
— это работает надёжно для браузеров. Для обычных (не браузерных)
приложений с собственным экраном логина откат на имя пакета приложения,
что совпадёт с записью только если пользователь сам вписал его в поле
"ссылка" — нетипично. Это ограничение текущей модели данных Passman
(ссылка на сайт, не идентификатор приложения), не баг этого кода.

## Структура

```
src-android/
  AndroidManifest.fragment.xml   — <service>/<activity> для вставки в манифест
  res/xml/autofill_service_descriptor.xml
  src/main/kotlin/com/trader/passman/autofill/
    PassmanAutofillService.kt    — находит поля пароля + домен, делегирует UnlockActivity
    UnlockActivity.kt            — биометрия → фоллбэк на мастер-пароль → поиск → заполнение
    BiometricVaultKeyStore.kt    — Keystore-ключ, обёртка vault key под биометрией
    VaultBridge.kt               — JNI-объявления, зовут src-tauri/src/mobile_ffi.rs
```

## Интеграция в сгенерированный Tauri-проект

Android-проект (`src-tauri/gen/android/`) создаётся/перезаписывается
командой `tauri android init` — поэтому эти файлы НЕ лежат прямо там (были
бы потёрты при регенерации). Порядок действий при реальной сборке:

1. `cd src-tauri && bun run tauri android init` (или `cargo tauri android init`).
2. Скопировать `src/main/kotlin/com/trader/passman/autofill/*.kt` в
   `src-tauri/gen/android/app/src/main/kotlin/com/trader/passman/autofill/`.
3. Скопировать `res/xml/autofill_service_descriptor.xml` в
   `src-tauri/gen/android/app/src/main/res/xml/`.
4. Вставить содержимое `AndroidManifest.fragment.xml` внутрь `<application>`
   в `src-tauri/gen/android/app/src/main/AndroidManifest.xml`.
5. В `src-tauri/gen/android/app/build.gradle.kts` добавить зависимость:
   ```kotlin
   dependencies {
       implementation("androidx.biometric:biometric:1.1.0")
   }
   ```
6. **Обязательно** собирать с `RUSTFLAGS="-C panic=unwind"` — см. комментарий
   в начале `src-tauri/src/mobile_ffi.rs` и в `.github/workflows/build.yml`.
   Без этого паника в Rust-коде обрушит процесс хост-приложения (например,
   браузера), а не просто покажет "не удалось".
7. `minSdkVersion` проекта должен быть ≥ 24 (биометрия/Keystore API, которые
   использует этот код, доступны начиная с этой версии; сам `AutofillService`
   — с API 26, но это гарантируется самой ОС: на более старых устройствах
   система просто никогда не попытается забиндиться к сервису).

Поскольку `tauri android init` перезатирает сгенерированный проект, шаги
2–5 нужно повторять после каждой регенерации — либо автоматизировать через
`build.rs`/скрипт копирования, либо (правильный путь на будущее) оформить
это как официальный Tauri mobile-плагин, который Tauri сам вливает в
проект при инициализации. Для первой рабочей версии выбран более простой
путь — обычные файлы для копирования, без инфраструктуры плагина.

## О биометрическом кэше

`BiometricVaultKeyStore` хранит vault key, обёрнутый AES-256-GCM ключом в
Android Keystore с `setUserAuthenticationRequired(true)` без льготного
периода — то есть каждое использование требует свежего биометрического
подтверждения, кэшируется не "разблокированное состояние", а только
возможность НЕ вводить пароль вручную каждый раз. Файл кэша
(`autofill_cached_key.bin`, в приватной директории приложения) без
Keystore-ключа бесполезен — Keystore не позволяет извлечь сырой ключ из
защищённого хранилища устройства.
